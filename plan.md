# План: Телеграм-бот «Настроение в каналах»

## 1. Идея и сценарий

Пользователь добавляет в бота интересные ему телеграм-каналы и нажимает кнопку-эмодзи,
отражающую настроение. Бот собирает сообщения этих каналов за последние N часов и через
LLM отбирает только те, что соответствуют выбранному настроению, затем присылает сводку.

Сценарий использования:

1. `/start` → приветствие + клавиатура: «➕ Каналы», «⏱ Период», «🎭 Настроение».
2. «➕ Каналы» → пользователь присылает `@username` или ссылку `t.me/name` — бот
   проверяет доступность и сохраняет. Кнопка «Мои каналы» показывает список с удалением.
3. «⏱ Период» → выбор N: 3 / 6 / 12 / 24 часа (по умолчанию 24).
4. «🎭 Настроение» → инлайн-клавиатура с эмодзи из `config.yaml` (по умолчанию
   😂 🔥 💡 и т.д., набор меняется правкой конфига).
5. Бот парсит сообщения из каналов пользователя за N часов, отправляет их батчем в LLM
   (OpenRouter), получает метки/оценки соответствия настроению, собирает топ-10 и отдаёт
   дайджест с ссылками на оригиналы.

## 2. Стек

- **Python 3.12+, aiogram 3.x** — фреймворк бота (по AGENTS.md).
- **OpenRouter API** (`OPENROUTER_API_KEY` уже в `.env.example`) — классификация сообщений
  по настроению через LLM.
- **httpx (aiohttp)** — запросы к Telegram Web (`t.me/s/...`) и OpenRouter.
- **BeautifulSoup4** — парсинг HTML превью каналов.
- **aiosqlite / SQLite** — хранение подписок и настроек; файл `bot.db` в `.gitignore`.
- **python-dotenv** — секреты из `.env`.
- **PyYAML** — декларативный конфиг бота `config.yaml`.

## 3. Как бот получает сообщения каналов

Bot API не даёт читать чужие каналы «снаружи», поэтому два канала данных:

1. **Публичные каналы — основной путь (без ключей).** Парсим HTML-превью
   `https://t.me/s/<username>`. Каждая страница = ~20 постов с датами
   (`<time datetime="...">`), текстом и ссылками. Для 24 часов хватает 1–3 страниц.
2. **Каналы, куда бот добавлен админом — запасной путь.** Включаем polling
   (`getUpdates`), сохраняем входящие посты канала в БД, отдаём их наравне с распарсенными.

При добавлении канала бот проверяет доступность: если `t.me/s/<name>` отдаёт 404 — канал
приватный или не существует; тогда предлагаем добавить бота в канал админом (путь 2).

### 4.1. Декларативный конфиг `config.yaml`

Вся кастомизация — в одном YAML-файле, код не трогаем:

```yaml
bot:
  name: "Настроение в каналах"
  admin_ids: [123456789]          # кому доступен /reload

moods:                            # ← кнопки-эмодзи и их смысл
  - emoji: "😂"
    label: "Смешное"
    prompt: "юмор, мемы, забавные ситуации"
    score_threshold: 7
  - emoji: "🔥"
    label: "Горячее"
    prompt: "сенсации, важные новости, скандалы"
    score_threshold: 7
  - emoji: "💡"
    label: "Идеи"
    prompt: "инсайты, неочевидные мысли, вдохновение"
    score_threshold: 6
  # можно добавить/убрать любые эмодзи без правки кода

llm:
  model: "openai/gpt-4o-mini"     # модель OpenRouter
  max_tokens: 4000
  temperature: 0.2
  batch_size: 30                  # постов на один вызов LLM
  timeout_sec: 90

period:
  default_hours: 24
  presets: [3, 6, 12, 24]         # кнопки выбора периода
  min_hours: 1
  max_hours: 72

digest:
  top_n: 10                       # сколько постов в сводке
  text_limit: 200                 # обрезка текста поста, символов
  min_score_default: 7            # порог, если не задан у настроения
  show_views: true
  show_reasons: true              # показывать объяснение LLM «почему подходит»

fetch:
  max_pages_per_channel: 3        # глубина парсинга t.me/s
  request_delay_sec: 1.0          # пауза между запросами (анти-429)
  cache_minutes: 30               # свежесть кеша постов

fallback:
  keywords_enabled: true          # эвристика по ключевым словам, если LLM упал

texts:                            # все пользовательские сообщения бота
  start: "..."
  no_results: "..."
  llm_failed: "..."
  meaning_of_life: "Смысл жизни найден. Можно расходиться"  # ответ на ввод 42
```

Правила работы с конфигом:

- `config.py` при старте читает YAML, валидирует (уникальные эмодзи, числа в диапазонах)
  и кладёт в единый объект `Settings`, который раздают в роутеры через `Dispatcher`.
- Эмодзи-кнопки в `handlers/mood.py` строятся динамически из `moods` — набор настроений
  меняется правкой YAML и рестартом/`/reload` без переписывания кода.
- Секреты (`BOT_TOKEN`, `OPENROUTER_API_KEY`) остаются в `.env`, в YAML их не кладём —
  репозиторий публичный.
- `/reload` (только для `admin_ids`) перечитывает `config.yaml` на лету — удобно крутить
  пороги и набор эмодзи прямо перед демо.
- `config.yaml.example` коммитим в репозиторий, реальный `config.yaml` можно не класть
  в `.gitignore` (секретов в нём нет), но пример обязателен.

## 5. Модель данных (SQLite)

```sql
CREATE TABLE users (
    tg_id      INTEGER PRIMARY KEY,
    hours_n    INTEGER DEFAULT 24,
    created_at TEXT
);
CREATE TABLE channels (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    tg_id      INTEGER NOT NULL,
    username   TEXT NOT NULL,
    mode       TEXT DEFAULT 'public',   -- public | admin_poll
    added_at   TEXT,
    UNIQUE(tg_id, username)
);
CREATE TABLE posts (                    -- кеш распарсенных постов
    id         INTEGER PRIMARY KEY,
    channel_id INTEGER NOT NULL,
    post_id    TEXT,                    -- ссылка/идентификатор
    text       TEXT,
    published  TEXT,
    views      INTEGER,
    UNIQUE(channel_id, post_id)
);
```

Кеш `posts` позволяет не перепарсивать каналы при повторных нажатиях на эмодзи.

## 6. FSM-состояния

- `AddChannel.waiting_username` — ждём `@username` / ссылку.
- `SetPeriod.waiting_hours` — ждём число часов (плюс кнопки-пресеты).

### 6.1. Пасхалка «42»

В `SetPeriod.waiting_hours` (и в любом другом месте, где принимается число) первым делом
проверяется: если пользователь прислал ровно `42` — вместо установки периода отвечаем
текстом `texts.meaning_of_life` («Смысл жизни найден. Можно расходиться»), состояние FSM
сбрасываем, период не меняем. Числа вне `[min_hours, max_hours]` из конфига отклоняем
с подсказкой, всё остальное — валидный период.

## 7. Карта настроений

Убрана из кода в `config.yaml` (см. §4.1, секция `moods`). В `models.py` остаётся только
dataclass `Mood(emoji, label, prompt, score_threshold)`, экземпляры которого создаёт
`config.py`. Кнопки эмодзи, их подписи, промпты для LLM и пороги — всё правится в YAML.

## 8. LLM-классификация (ядро, `services/classifier.py`)

Для выбранного настроения M (из конфига):

1. Собираем все посты за N часов из каналов пользователя (из кеша/парсера), у каждого —
   короткий `id` (1..K).
2. Батчами по `llm.batch_size` постов отправляем в OpenRouter (модель из `llm.model`)
   промпт вида:

   > «Ниже список сообщений телеграм-каналов в формате `[id] | текст`. Отбери те, что
   > соответствуют настроению „{label}" ({prompt}). Верни строго JSON-массив id и для
   > каждого — оценку соответствия 0–10 и одно предложение, почему подходит. Не выдумывай
   > id, которых нет в списке.»

3. Парсим JSON (`json.loads` + страховочный regex-парс, если модель обернула в markdown).
4. Фильтруем по порогу `score_threshold` конкретного настроения (или `min_score_default`),
   сортируем по убыванию, берём `digest.top_n`.
5. Фолбэк: если LLM недоступен и `fallback.keywords_enabled` — эвристика по ключевым
   словам, выводимым LLM-промптом заранее (сообщение пользователю «LLM недоступен,
   упрощённый фильтр»).

Батчинг обязателен: N часов × несколько каналов = сотни постов, один вызов на всё
медленнее и дороже, чем 3–5 батчей по 30.

## 9. Формат сводки (`services/digest.py`)

```
🎭 Настроение: 😂 Смешное
📡 Каналы: @tech, @humor | Период: 24 ч
Найдено: 47 → топ-10

1. [🔥 9/10] Текст поста... (обрезано до 200 симв.)
   @tech · 14:20 · 12.3K просмотров
   t.me/tech/1234
...
```

Каждый пункт — ссылка на оригинал. Плюс кнопки: «Обновить», «Другое настроение».

## 10. Порядок реализации (милестоуны)

| # | Шаг | Результат |
|---|-----|-----------|
| 1 | `config.yaml` + `config.py` (загрузка/валидация) + `db.py` + `models.py` | бот полностью конфигурируется файлом |
| 2 | `bot.py` + `/start` + главное меню (кнопки из конфига) | бот отвечает, кнопки на месте |
| 3 | `handlers/channels.py` (FSM + проверка доступности) | каналы добавляются/удаляются |
| 4 | `handlers/period.py` (пресеты из конфига) | выбор N часов сохраняется |
| 5 | `services/fetcher.py` — парсер `t.me/s` | посты из публичных каналов |
| 6 | `services/classifier.py` — вызов OpenRouter | LLM возвращает id+оценки |
| 7 | `handlers/mood.py` (эмодзи из YAML) + `services/digest.py` | эмодзи → сводка в чат |
| 8 | `/reload`, фолбэки, кеш, «Обновить» | демо не падает, конфиг крутится на лету |

Оценка: 2.5–3.5 часа работы пилота.

## 11. Риски и фолбэки

- **`t.me/s` может отдать капчу/429** при частых запросах → кеш в `posts`, паузы между
  запросами, лимит 1–2 страницы на канал.
- **LLM медленный** (5–20 сек на батч) → показываем статус «Анализирую...», уменьшаем
  окно N, дешёвая модель.
- **LLM отдаёт невалидный JSON** → regex-извлечение массива, повторный вызов с требованием
  «только JSON».
- **Приватный канал** → предложение добавить бота админом, иначе отказ с пояснением.
- **Пустой результат** → «За N часов ничего подходящего не нашлось, попробуй другой период».
- **Демо без интернета/лимитов** → заранее записать видео работы бота.
